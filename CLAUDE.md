# Product Spec: Pulse — macOS Personalized News & Intelligence Dashboard

You are building a macOS desktop application called **Pulse** using **Electron** and **React**. This is a personalized news intelligence dashboard with two equal halves: **Finance** (stock portfolio intelligence for a semiconductor-focused value chain investor) and **General News** (US geopolitics, local/regional news, space exploration, and world events). Both halves should receive equal UI real estate, feature depth, and design attention. The app lives in the macOS menu bar with an expandable full window.

---

## User Profile & Interests

The user has two equally important areas of interest:

### Finance Half — Portfolio Context
The user is a value chain investor with the following portfolio composition:
- **~80%+ Semiconductor stocks** spanning the full value chain: fabless AI chip designers (e.g., NVIDIA, AMD, Broadcom), foundries (e.g., TSMC, GlobalFoundries), equipment manufacturers (e.g., ASML, Applied Materials, Lam Research, KLA), EDA tools (e.g., Synopsys, Cadence), industrial gases and materials suppliers (e.g., Air Liquide, Linde), and semiconductor packaging/testing (e.g., ASE, Amkor).
- **Defense & propulsion** stocks (e.g., Lockheed Martin, Northrop Grumman, RTX, Aerojet Rocketdyne).
- **Mining** stocks (e.g., rare earth, lithium, copper — supply chain inputs for semiconductors and defense).

This context should deeply inform default RSS feeds, keyword lists, urgency scoring logic, and the stock discovery feature. The app should understand semiconductor supply chain dynamics — for example, an export control on ASML's EUV equipment impacts foundries, which impacts fabless designers, which impacts AI companies.

### General News Half — Personal Interests
The user wants to stay informed on:
- **US Geopolitics:** Domestic policy, elections, legislation, foreign relations, trade policy, congressional activity, executive actions.
- **Local & Regional News:** News from specific cities, states, countries, and regions that the user configures. The user should be able to add/remove geographic areas of interest just like they add/remove stock tickers.
- **Space Exploration:** NASA, SpaceX, ESA, ISRO, commercial space, planetary science, missions, launches, astronomy.
- **World Events:** Major international developments, conflicts, diplomacy, humanitarian events.

Both halves should have equally robust urgency scoring, notification support, and UI treatment.

## Architecture Overview

### App Shell
- **Menu bar tray icon** using Electron's `Tray` API with a dropdown popover window showing a quick-glance feed of recent headlines and unread count badge.
- **Expandable full window** using `BrowserWindow` (activated from tray icon click or keyboard shortcut) with the complete dashboard UI.
- The app should support **launch at login** using Electron's `app.setLoginItemSettings()` and run as a background process by keeping the tray alive when the main window is closed.

### Tech Stack
- **Runtime:** Electron (latest stable)
- **Frontend:** React 18+ with TypeScript
- **Bundler:** Electron Forge or Electron Vite (prefer Electron Vite for faster dev experience with React)
- **State Management:** Zustand (lightweight, minimal boilerplate) or React Context for simpler state
- **Data Persistence:** `better-sqlite3` for the main process database (article history, read/unread state, bookmarks, feed configurations, portfolio watchlist). Communicate between main and renderer via IPC (`ipcMain` / `ipcRenderer`).
- **RSS Parsing:** `rss-parser` npm package (handles RSS 2.0, Atom, and RDF feeds)
- **In-app browser:** Electron `<webview>` tag or `BrowserView` for full article reading within the app
- **Notifications:** Electron's `Notification` API for native macOS notifications
- **Local AI:** Integration with Ollama via its local REST API (`http://localhost:11434/api/chat`) using `fetch` from the main process
- **Styling:** Tailwind CSS or CSS Modules — keep it utility-first for rapid iteration

### Process Architecture
- **Main process:** Feed polling, SQLite database, Ollama communication, notification dispatch, tray management. All background work happens here.
- **Renderer process:** React UI. Communicates with main process via IPC for data and actions.
- Define a clean IPC API layer — avoid scattering `ipcRenderer.invoke()` calls throughout React components. Create a `preload.ts` that exposes a typed `window.api` object.

### 5. Urgency Scoring & Notifications

This is the most critical feature. Use a **pluggable architecture** — define a TypeScript interface for scoring strategies so the implementation can be swapped. Urgency scoring applies to **both halves** of the app — finance and general news — with separate keyword dictionaries.

**Default implementation: Keyword Pre-filter → Ollama for Ambiguous Articles**

**Step 1 — Keyword Pre-filter (instant):**

Maintain curated keyword dictionaries per urgency tier, split by domain:

**FINANCE urgency keywords (when matched alongside a portfolio ticker/sector):**
- Regulatory/legal: "antitrust," "lawsuit," "SEC," "investigation," "sanctions," "export control," "ban," "tariff," "indictment"
- Financial events: "earnings," "revenue miss," "guidance," "downgrade," "upgrade," "acquisition," "merger," "IPO," "bankruptcy," "delisting"
- Operational: "fab fire," "supply shortage," "recall," "outage," "shutdown," "yield issues"
- Geopolitical (finance-relevant): "Taiwan strait," "China ban," "CHIPS Act," "entity list," "embargo"
- Leadership: "CEO resign," "CEO fired," "executive departure," "board shakeup"

**GENERAL NEWS urgency keywords (when matched alongside a geographic interest or topic area):**
- Breaking events: "breaking," "just in," "developing," "emergency," "alert"
- Geopolitical: "war," "invasion," "ceasefire," "summit," "treaty," "coup," "assassination," "election results," "impeachment," "executive order"
- Space: "launch," "landing," "mission failure," "discovery," "first ever," "crewed mission," "Mars," "Moon"
- Safety/local: "tornado," "earthquake," "wildfire," "evacuation," "shooting," "explosion," "state of emergency"
- Policy: "passed," "signed into law," "overturned," "Supreme Court," "veto," "sanctions"

*Low priority (batch) for both domains:*
- General industry commentary, opinion pieces, product reviews, hiring announcements, conference recaps.

*Scoring logic:*
1. Determine if the article belongs to the Finance or General News domain (based on feed category).
2. **Finance articles:** Check if headline + summary contains any portfolio ticker, company name, or sector keyword. If match + finance urgency keyword → URGENT. If match but no urgency keyword → AMBIGUOUS, send to Ollama. If no match → LOW.
3. **General news articles:** Check if headline + summary contains any geographic interest keyword or topic area keyword. If match + general news urgency keyword → URGENT. If match but no urgency keyword → AMBIGUOUS, send to Ollama. If no match at all → LOW.

**Step 2 — Ollama Scoring (for ambiguous articles only):**

- Send the article's **headline + summary only** (not full body) to Ollama via `fetch('http://localhost:11434/api/chat', ...)` from the main process.
- Recommended models (in order of speed on Apple Silicon with MPS): `phi3:mini` (3.8B, fastest), `mistral:7b` (good balance), `llama3:8b` (most capable).
- Use domain-appropriate prompts:

*Finance prompt:*
```
You are a financial news urgency scorer. Given a news headline and summary, score its urgency from 1-5 for an investor holding the following stocks: [TICKER_LIST].

Consider: Does this news directly impact any of these holdings? Could it affect their supply chain, customers, or competitors? Is this breaking news or routine coverage?

Respond in JSON only: {"score": N, "reason": "brief explanation"}
```

*General news prompt:*
```
You are a news urgency scorer. Given a news headline and summary, score its urgency from 1-5 for a person interested in the following topics and locations: [INTERESTS_LIST].

Consider: Is this breaking or developing news? Does it directly affect one of these areas? Is this a significant event or routine coverage? Would someone want to know about this immediately?

Respond in JSON only: {"score": N, "reason": "brief explanation"}
```

- Score 4-5 → URGENT, notify immediately.
- Score 2-3 → MEDIUM, include in next batch digest.
- Score 1 → LOW, no notification.

**Graceful degradation:** If Ollama is not running or unreachable, fall back to keyword-only scoring. Show a subtle indicator in the app that AI scoring is offline.

**Notification Behavior:**
- **Urgent articles:** Immediate native macOS notification via Electron's `Notification` API with headline, source, and urgency reason. Clicking the notification should focus the app and open the article.
- **Batched digest:** Every 15-30 minutes (user-configurable), send a single notification summarizing new articles: "12 new articles: 3 about NVDA, 2 geopolitics, 1 space..."
- **Notification preferences:** Per-category toggle for enabling/disabling notifications. Global quiet hours setting.

- Use `Promise.allSettled()` for concurrent feed fetching (don't let one failing feed block others).
- Deduplicate articles by URL and/or GUID.
- Track `ETag` and `Last-Modified` headers to avoid re-downloading unchanged feeds.
- Respect feed TTL (time-to-live) values if present.
- Use `setInterval` or a scheduling library for periodic polling. Consider using Electron's `powerMonitor` to pause polling when the system is sleeping.

## Design & UI Guidelines

**Aesthetic: "Bloomberg meets Reeder"**
- **Data-dense but clean.** Information-rich layouts with strong visual hierarchy.
- **Typography-driven.** Use Inter or system font stack with clear weight contrast between headlines, metadata, and body text. Tight line spacing for density.
- **Minimal chrome.** No unnecessary borders, shadows, or decorative elements. Let whitespace and alignment create structure.
- **Color palette:** Dark mode primary (respect system appearance via `nativeTheme`). Use a restrained accent color (e.g., electric blue or amber) for urgency indicators and interactive elements. Red/orange for urgent, green for positive signals, muted gray for low-priority.
- **Grid layout:** The main window should use a sidebar (feed list / categories, split into Finance and General News sections with clear visual separation) + main content area (article list) + detail pane (article reader) — similar to Mail.app or Reeder's three-column layout. The sidebar should have two top-level sections: **Finance** and **News**, each expandable into their category folders. Consider a tab bar or segmented control at the top of the article list to switch between "All," "Finance," and "News" views.
- **Menu bar popover:** Compact, scannable list of recent headlines with urgency dots, grouped or tagged by domain (Finance/News). Unread count badge on the tray icon.
- **Animations:** Subtle, fast, purposeful. Use CSS transitions — no gratuitous animations.
- **Density control (nice-to-have):** Let the user toggle between compact and comfortable spacing.
- **Window behavior:** Closing the main window should hide it (not quit the app). The app stays alive via the tray icon. Cmd+Q quits fully.

## Implementation Order

Build the app in this sequence for incremental progress:

1. **App shell:** Electron app with tray icon + empty main `BrowserWindow` with three-column layout. Tray click opens a small popover window. Closing main window hides it. Set up Electron Vite + React + TypeScript + Tailwind.
2. **SQLite database:** Define schema, set up `better-sqlite3`, create migration system, wire up IPC layer between main and renderer.
3. **RSS feed parsing & polling:** Implement feed fetching with `rss-parser` in the main process, store articles in SQLite, expose via IPC.
4. **Article list & reading:** React components to display articles, open full articles in `<webview>`. Include domain filter (All / Finance / News).
5. **Category management:** Create/edit folders, assign feeds to Finance or News domain.
6. **Portfolio watchlist (Finance half):** Ticker search, add/remove, portfolio-based article filtering.
7. **Geographic interest management (News half):** Location search, add/remove, location-based article filtering.
8. **Keyword urgency scoring:** Implement pre-filter with keyword dictionaries for BOTH finance and general news domains.
9. **Notifications:** Immediate + batched digest using Electron `Notification` API, covering both domains.
10. **Ollama integration:** Score ambiguous articles (both domains) via local REST API, graceful fallback.
11. **Stock discovery:** Weekly list, daily drip, AI-curated suggestions.
12. **Settings/preferences:** Poll interval, notification preferences, quiet hours, density toggle, launch at login.
13. **Packaging & polish:** Use Electron Forge or electron-builder to create a `.dmg`/`.app`. Add app icon, animations, edge cases, cleanup.
